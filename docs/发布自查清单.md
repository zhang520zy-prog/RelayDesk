# RelayDesk 发布自查清单

> 每次修改工作流 / 打包配置 / 版本号 / 依赖后、推送触发 CI 前，先跑
> `scripts/pre-flight.sh`（加 `--full` 连前端构建一起验），全绿再推。
> 本清单记录历次构建失败的根因与对应自查点，新增踩坑请追加。

## 一、历史失败记录（按发生顺序）

## 二、git 推送层问题

- **`HTTP 408 / HTTP2 framing layer / Connection reset`**：~90MB 包走本机 Clash TUN 易断。
  - 先 `git ls-remote relaydesk main` 对比本地 sha——很多"失败"其实已经推上去
  - 重试：`git -c http.postBuffer=524288000 push --force relaydesk main`
  - `Everything up-to-date` 出现时一定以 `ls-remote` 为准，勿盲信
- **远端 main 是重写历史**（每次推送 squash），local main 用 `git commit-tree` 生成——推送必须 `--force`。

## 三、发布前 30 秒检查（跑 `scripts/pre-flight.sh` 已覆盖）

1. 三个 `tauri.*.conf.json` 无非法属性（#1）
2. `NSIS_HOOK_POSTUNINSTALL` 宏名正确、`!macro/!macroend` 配对（#12）
3. 所有 `@tauri-apps/*` npm 包 minor == 对应 crate minor（#8 #9）
4. `package.json` / `tauri.conf.json` / `Cargo.toml` 版本号三处一致（#11 前置）
5. `rust-toolchain.toml` 与全部 workflow 钉 1.90（#5）
6. `bundle.createUpdaterArtifacts=true`、pubkey、endpoints、bundles 含 app、签名 env 齐全（#2 #4 #7 #10）
7. 本地私钥能完成一次真实签名（#3）
8. `pnpm-lock.yaml` 与 `package.json` 无漂移（frozen-lockfile 必过）

## 四、发布后验证清单

- `latest.json` 含 `windows-x86_64` / `linux-x86_64` / `darwin-aarch64` 三个 platform
- 每个 platform 的 `url` 与 `signature` 对应文件名存在于 release assets（v2 原生：`-setup.exe`+`.exe.sig`、`AppImage`+`.sig`、`.app.tar.gz`+`.sig`）
- 版本号升级后旧客户端能在设置页检测到更新（更新判断靠 `latest.json.version` > 本机版本）
- Windows 卸载时实测"是否删除本地数据"弹窗出现（NSIS 钩子仅能在真机验证）

## 三、发版流程约定

- **每个 tag 必须配 `docs/releases/vX.Y.Z.md` 更新日志**（打 tag 前提交）。`publish-release` 用它做 Release 正文，`assemble-latest-json` 把内容注入 `latest.json.notes`（应用内"关于"页更新说明）。缺失时回退为上一个 tag 以来的 git log 摘要。
- 版本号四处同步：`package.json` / `tauri.conf.json` / `Cargo.toml` / `Cargo.lock`。
- 本地已装旧版客户端用于验证热更新链路（检查→下载→安装），发版后不要在本地重建覆盖。
- **CI 构建门 = `cargo clippy -- -D warnings` + `pnpm format:check`**：本地 `cargo check` 只告警不失败，CI 视警告为错误。发 tag 前必须本地跑一遍全量 clippy（本次 v3.21.0 因 8 个 lint + 9 个 prettier 文件失败）。
