# RelayDesk 全局 UI 设计规范：清爽渐变 + 轻玻璃

## 目标

把 RelayDesk 统一为简约、现代、清爽的桌面控制中心。以现有 RelayDesk 青绿色为唯一品牌主色，通过同色相的明度、透明度和渐变建立层级；用轻玻璃材质区分看板、筛选区和临时反馈；减少用户在相关操作之间的移动距离，同时保证按钮有足够的安全间距。

本轮只调整 renderer 的视觉、布局、交互反馈和文案呈现，不改变已有 relay API、登录会话安全策略、重启状态机、充值流程或用量数据来源。

## 视觉语言

### 色彩

- 品牌基准色保持 `#138b78` 附近的 RelayDesk teal。
- 浅色主题使用从 `#effbf8` 到 `#e7f2fb` 的轻微同色偏冷渐变作为页面背景与主看板背景；主按钮使用实色 teal。
- 深色主题使用从 `#0d181c` 到 `#102b2d` 的低对比渐变；按钮使用提亮 teal，文字仍以高对比中性灰为主。
- 不新增第二品牌色。成功、警告、失败只作为语义反馈色，面积小于主色区域。
- 图表继续使用独立可辨识色，但模型明细、图例、曲线和柱状图保持同一模型同色。

### 材质与层

从下到上固定为四层：

1. **Canvas**：窗口背景和页面渐变。
2. **Surface**：导航、普通内容卡片，半透明或纯色表面，边界清楚。
3. **Glass panel**：筛选区、统计总览、充值汇总、登录辅助卡，使用 `backdrop-filter`（不可用时自动回退为不透明表面）、细边框和轻阴影。
4. **Action layer**：主按钮、确认对话框、错误提示，使用实色或语义色，不使用透明玻璃承载关键操作。

玻璃只用于表达分组和层级，不用于装饰整页；阴影遵循一套小、中、大三级，避免每个卡片单独定义阴影。

## 排版和尺寸

- 全应用使用一个 UI 字体栈：`Inter, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`；等宽内容继续使用现有 mono 栈。
- 正文基准 14px，辅助文本 12px，最小普通正文不低于 12px。
- 页面标题 24px / 1.2，区块标题 16px / 1.35，卡片标题 14px / 1.4，按钮文本 13px / 1.2。
- 重要数值使用 28–32px，统计表格数字使用 12–13px 并启用等宽数字。
- 字重只使用 400、500、600；页面标题和主数字使用 600，普通说明使用 400，标签和按钮使用 500。
- 统一 4/8px 间距节奏：4、8、12、16、20、24、32。页面区块之间至少 20px，按钮之间至少 8px，主要操作之间至少 12px。

## 全局布局

- 保留左侧导航和顶部标题栏，但强化导航当前项的背景、左侧标记和文字对比度。
- 内容区使用 `max-width` 1180px，桌面大窗口居中；窗口变窄时保持 20px 内容内边距并允许纵向滚动。
- 每个页面只保留一个主动作。刷新、查看指引、取消等动作降为次级按钮。
- 相关动作必须在同一操作区：模型应用结果与重启入口在同一工具栏，充值选择与付款汇总相邻，用量筛选与图表控制同组排列。
- 图标按钮必须有可访问名称；图标旁已有文字时图标为装饰性元素。
- 任何按钮视觉高度至少 36px，关键确认和付款动作至少 40px；相邻点击目标至少 8px 间隔。

## 页面落地

### 登录页

- 使用单列主表单 + 侧边品牌说明的轻玻璃布局；小窗口自动隐藏侧边说明。
- 账号、密码和提交动作保持垂直顺序，字段间 12px，提交按钮与字段组间 20px。
- 不恢复钥匙串或密码持久化。页面明确提示会话仅保存在当前运行中；登录失败就地显示错误。
- 语言切换、帮助和返回动作放在表单顶部或底部同一操作区，避免分散到两侧。

### 模型中心与应用目标

- 顶部只放页面主标题、当前配置状态和一个主动作；帮助入口保持纯说明。
- 当前模型卡、分组选择和模型表格按照“当前状态 → 选择 → 应用”顺序排布。
- 应用成功提示、启动询问和重启工具继续沿用现有真实状态；视觉上使用同一 action layer。
- 分组映射卡采用三列（桌面）或单列（窄窗），每张卡保留目标状态、覆盖状态和保存反馈。

### 钱包与充值

- 顶部先展示余额、累计消费和更新时间三个摘要卡；余额卡使用主色渐变作为唯一强调。
- 充值区分成“选择金额 / 支付方式”与“本次充值汇总”两个玻璃面板，金额按钮三列排列，付款按钮只出现在汇总面板。
- 付款按钮打开官方收银台；页面明确显示金额、支付方式和“付款前在官方页面复核”的说明，不伪造应用内付款成功。
- 充值记录放在充值区下方，采用紧凑表格，空状态只保留一句说明和刷新动作。

### 用量统计

- 顶部顺序为筛选 → 当前筛选汇总 → 图表控制 → 单一选中的图表 → 模型明细 → 详细表格。
- 同时只展示一种图表；分时曲线、柱状图和占比图通过选择器切换。
- 图表区使用玻璃面板，模型明细在 1440px 以上与图表并排，在 1000px 以下堆叠；图例带颜色、模型名、数值和占比。
- 数据不完整、检测失败或字段缺失必须保留真实状态提示，不用“看起来完整”的占位数据。

### 设置、工具部署和环境医生

- 设置页保留偏好与环境入口；工具部署继续作为显眼的独立导航入口，不与设置重复承载相同动作。
- 环境医生检查列表使用分组卡片和明确状态标签；检测中、失败、未安装和已安装状态有不同语义色和文字。
- 安装确认使用 action layer 对话框，明确平台、工具、权限和下一步；不自动安装、不静默降级。

## 主题和响应式规则

- 浅色、深色和跟随系统共享同一层级结构，只切换背景、表面、边框和文字 token。
- 900×600：导航可折叠，页面内容单列，控制组允许换行，保持无横向滚动。
- 1000×650：充值选择区和付款汇总上下排列；图表明细堆叠但压缩垂直留白。
- 1440×900：统计图表与模型明细并排；设置和应用目标使用多列布局。
- 所有动画使用统一 140–220ms 过渡，并尊重 `prefers-reduced-motion`。

## 验收标准

- 所有新增或调整文案中英文同步。
- 全局按钮、字段和卡片使用同一 token，不出现组件级硬编码颜色和随意字体。
- 浅色、深色、跟随系统以及导航展开/折叠均无横向溢出。
- 关键按钮有足够间距、禁用/加载/失败状态清晰，键盘焦点可见。
- 不改变真实 API 调用与安全边界；不调用钥匙串、不执行真实充值、不自动重启或启动进程。
- 通过 TypeScript、前端单测、renderer production build、`git diff --check`；Rust 相关代码未改动时复用最近一次 Rust 检查结果并在交付说明中标明。
