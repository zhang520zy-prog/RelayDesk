# RelayDesk 钱包、充值与用量 UI 实施计划

## 目标

在保留当前 RelayDesk 未提交实现的前提下，补齐钱包与充值、用量统计、登录入口和侧栏导航的可审阅 UI。Renderer 只通过 Rust/relayApi 适配层获取数据；在中转站未提供正式订单查单和模型聚合契约时，明确展示不可用/降级状态，不伪造支付成功、到账、账单或工具归因。

## 范围与顺序

1. 先补失败测试：导航、钱包状态与金额/支付方式选择、订单不可用提示、用量按模型单表、缺省字段与未归因、登录注册/找回密码/记住密码安全边界、双语键对齐及局部横向滚动。
2. 新增 relayApi 的只读钱包/用量 DTO 和 invoke 适配接口；不在本轮写真实支付闭环或直接请求站点。
3. 修改 RelayDeskApp、Sidebar、AppShell 和 locales，加入钱包与用量页面入口与页面标题。
4. 新增 WalletPage：余额摘要、配置加载/失败/不可用、金额与支付方式选择、实付预览占位状态、订单历史/查单接口未提供说明，所有不可执行动作明确为未就绪。
5. 新增 UsagePage：时间范围、摘要、按模型对比单表（输入/输出/总 Token、缓存读写、费用、成功率、工具来源），缺少字段显示破折号，分页不完整不显示区间总计。
6. 登录页增加注册、找回密码官方入口和仅系统凭据库可用的记住密码控件；当前没有安全凭据适配时保持禁用并说明原因，不写入 localStorage。
7. 单独整理接口需求文档，包含已观察路径、请求/响应最小字段、待站点确认事项、未实现边界。
8. 完成新鲜验证：pnpm typecheck、pnpm test:unit、renderer production build、cargo test --lib、cargo fmt --check、git diff --check，并做 900×600、1000×650、1440×900 中英文/深浅/跟随系统/侧栏展开折叠视觉走查。

## 交付门槛

- 所有新增文案中英文键对齐。
- 充值不可执行时不得出现可点击假支付按钮；订单状态接口缺失必须可见。
- 用量主表按模型一行并标注数据完整性；不把本地 usageApi 当中转站账单。
- 未完成项及原因先交给用户审阅；只有用户明确确认可交付后才生成最终 Handoff 简报。
