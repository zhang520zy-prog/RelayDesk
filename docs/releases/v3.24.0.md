## RelayDesk v3.24.0

本版本核心：Claude 桌面端（Claude.app）正式打通中转站——全新安装无需 Anthropic 账号即可使用；模型中心按 AI 程序分区重组；新增自定义 API 供应，可把别家中转站接进 RelayDesk。

### Claude 桌面端打通（免登录）

- **全新安装免登录**：应用模型到 Claude 时自动写入 Claude.app 的 3p 推理网关 profile（`deploymentMode: 3p` + `inferenceGatewayBaseUrl` 指向中转站 + 分组专用 key），不再卡在官方登录页——这是 cc-switch 桌面端免登录的同款机制，profile 独立不与其互踩
- **全组模型进菜单**：Desktop 模型菜单一次写入该分组全部可路由模型，不再只有当前选中的一个
- **自动屏蔽不可服务模型**：按分组 key 调用 `/v1/models` 校验上游真实可服务集合，pricing 列表里实际不可路由的模型（如 Kiro 组的部分 claude id）不再写进 profile——修复「Gateway couldn't serve」报错
- **一切入口生效**：应用/托盘切换/deeplink/供应商切换全部触发桌面端写入；切回官方供应商自动恢复 1p 模式；接管模式占位凭据不误写
- **跳过登录门卡**：`primaryApiKey` + `hasCompletedOnboarding` 随应用自动增量写入（不覆盖用户既有配置），新机首次启动 CLI 不再弹确认
- **桌面端启动核验**：检测/启动校验 `CFBundleIdentifier`，同名冒充的 `Claude.app` 不再被误识别、误拉起；厂商桌面端标注「需官方账号」提示，引导无账号用户用命令行

### 模型中心：按 AI 程序分区

- 目录改为**程序化分节**：Claude / ChatGPT / Gemini / Grok / Devin / 其他，每节带程序图标、名称与分组数，一眼看清归属；跨家族分组在各相关节同时出现
- 顶部程序徽标变为**筛选器**：点选只显示该程序一节，再点恢复全部；「设置应用目标」入口保留
- 每个程序节内嵌**紧凑供应区**：该程序的自建供应一行展示 + `+` 快速添加（自动勾选当前程序）

### 自定义 API 供应

- **凭证页顶部**新增「自定义供应」区：别家中转站或自建 API 一份凭据同步到勾选的程序（claude/codex/gemini/grok），与本站账号并存
- 添加表单：**测速**（端点延迟实测）、**获取模型**（拉取 `/v1/models` 转多选清单，勾选项进 Claude 桌面端菜单）、API Key **显隐切换**
- 使用/删除一键完成；启用后 claude 桌面端 profile 同步更新

### 账号稳定性

- 修复「频繁登出/记住密码无效」：长效系统令牌解析此前只认单一响应形状，部分中转站返回对象/数组导致每次降级 15 分钟短票；现兼容多种信封并在降级时记录真实原因
- 登录会话内用量接口持续走真实凭据，密钥材料不入日志

### 更新与发布

- 本地构建不再误报「更新服务未配置」：`tauri.conf.json` 的 updater 端点纳入判定；更新检查结果写入诊断日志（「发现新版本/已是最新/失败原因」）
- 发布管线加固：latest.json 与安装包**同批原子上传**（消灭更新端点 404 窗口）、test-build 桥接 release 免于清理、tag 与版本号不一致直接拒发、`.sig` 缺失即失败、发后自动验证端点可达

### 工程清理

- 移除前端死封装与其对应后端命令/服务/类型、托盘死函数、未用依赖（`smol-toml`）；测试与 lint 全量通过
